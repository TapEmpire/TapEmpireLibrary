# TEL 3.01.00 — migration guide

Level execution, the message bus, level save data and the game/settings services moved from the
game project into TEL. Every section below lists what changed in **TEL** and what had to change in
the **project** (done in PopDrop, to be repeated in WordGame).

Serialized changes are called out separately — they do **not** produce compile errors and will
silently null out if missed.

---

## 1. Level execution moved to TEL

**TEL** — new `Runtime/CoreSystems/LevelExecutionCoreSystem/`:

| File | Notes |
|---|---|
| `Data/LevelExecutionData.cs` | typed on `TapEmpire.Level.LevelSettings`; `OnResourceSpent`/`ResourceSpent` removed (unused) |
| `Data/LevelStateData.cs` | `AddStepDone` now sets `LevelState.Won` when `StepsDone >= StepsTotal`; `IsOver` and `SetStepsTotal` removed |
| `Data/LevelState.cs`, `Data/LevelEndReason.cs`, `Data/FlowAction.cs` | enums, previously inside the interface file |
| `ExecutionActions/{Ads,Iap,Network,RateMe}ExecutionAction.cs` | unchanged behaviour |
| `ILevelExecutionCoreSystem.cs` + `LevelExecutionCoreSystemExtensions.cs` | see API changes below |
| `LevelExecutionCoreSystem.cs` | new base class |
| `Progress/ProgressExtensions.LevelExecution.cs` | see section 4 |

`ILevelExecutionCoreSystem` API changes:

- Signals are **R3-only**. `OnLevelStarted` / `OnLevelCompleted` are now `Subject<T>`; the
  `event Action<>` duplicates are gone, and `OnCycleCompleted` became `Subject<int>`.
- `RestartLevel(bool isDebug)` → `RestartLevel()` (the parameter was never read).
- `TryGetCamera` extension removed.
- `Levels` is typed `IReadOnlyList<TapEmpire.Level.LevelSettings>`.

The new `LevelExecutionCoreSystem` base owns: `ExecutionData`, `ExecutionModules`,
`_defaultLevelView`, `_diContainer`, `_coreSceneReferences`, `_disposables`, `_executionAction`,
`OnRelease`, `virtual DestroyLevel()`, `InitializeLevelView()`, `InstantiateLevelView()`,
`InitializeModules()` and `virtual OnLevelStateChanged()`.

**Project**:

- Delete the moved files; the game class derives from the TEL one:
  `class LevelExecutionCoreSystem : TapEmpire.CoreSystems.LevelExecutionCoreSystem, ILevelExecutionCoreSystem`.
- Rename the game class's `[Inject] Construct` → `ConstructDerived` and drop the `DiContainer` and
  `ICoreSceneReferences` parameters (the base injects them). Zenject injects both methods, base first —
  they must not share a name.
- Delete the game copies of `DestroyLevel`, `InitializeLevelView`, `InstantiateLevelView`,
  `InitializeModules`, and the no-op `OnInitializeAsync` override.
- Keep game-only bits as overrides: `DestroyLevel()` calling `base` then closing the level-end popup,
  and `OnLevelStateChanged()` for the win/lose flow.
- Migrate event subscribers to R3: `x.OnLevelCompleted += H` → `x.OnLevelCompleted.Subscribe(H).AddTo(_disposables)`.
  In PopDrop this was `AnalyticsCoreModule` and `CustomCursorUIView`.

## 2. Scene references consolidated

**TEL** — `TapEmpire.Level.ICoreSceneReferences` / `CoreSceneReferences` / `CoreSceneInstaller` are
now the only copies. The property is `LevelParent` (singular).

**Project** — delete the game's duplicate trio. The game had `LevelsParent` (plural) and its own
interface; the level system now injects TEL's.

**Serialized** — every `CoreSceneReferences` and `CoreSceneInstaller` component must be repointed to
TEL's script GUIDs, and the field names change because TEL uses `[field: SerializeField]`:

```
_light             -> <Light>k__BackingField
_backgroundSprite  -> <BackgroundSprite>k__BackingField
_levelsParent      -> <LevelParent>k__BackingField
```

In PopDrop this hit 4 `CoreSceneReferences` + 2 `CoreSceneInstaller` instances across `Core.unity`,
`Menu.unity` and TEL's own `Samples/Contexts/CoreContext.prefab` (which had been pointing at the
game's scripts).

## 3. Message bus moved to TEL

**TEL** — `TelMessageType` renamed to `MessageType` and gained `StartLevel` / `EndLevel`. New
`Messages/Data/LevelMessageData.cs` holds `LevelMessageData` (with `LevelIndex`) plus empty
`StartLevelMessageData` / `EndLevelMessageData` derivatives. `MessagesUtility`'s private helpers use
a `TMessageType` generic parameter (it previously shadowed the enum's new name).

**Project** — delete the game's `MessagesUtility`, `IMessageData`, `MessageType` and the two data
classes; they were duplicates. Repoint listeners to `TapEmpire.Messages` and `MessageType.EndLevel`.

`StartLevelMessageData` lost its constructor — construct with an initializer:
`new StartLevelMessageData() { LevelIndex = i }`.

For game-specific messages, add a partial half rather than a second utility:

```csharp
public enum PopDropMessageType { }

public static partial class MessagesUtility   // namespace TapEmpire.Messages
{
    private static readonly Dictionary<PopDropMessageType, List<Delegate>> GameCallbacks = new();

    public static void Subscribe<T>(PopDropMessageType t, Action<T> cb) where T : IMessageData
        => Subscribe(t, cb, GameCallbacks);
    // + Unsubscribe, Invoke
}
```

## 4. Level save data moved to TEL

**TEL** — `Runtime/CoreSystems/LevelExecutionCoreSystem/Progress/ProgressExtensions.LevelExecution.cs`
holds a `LevelSaveData` base (just `LevelName`) and generic extensions:

```csharp
T    GetLevelSaveData<T>()  where T : LevelSaveData, new()
void SetLevelSaveData<T>(T) where T : LevelSaveData
void CleanLevelSaveData()
bool HasLevelSaveData()
string GetLevelSaveName()
```

Storage stays `StringValuesDictionary` via `Get/SetSerializableObject`, so it remains part of the
cloud-save snapshot. `HasLevelSaveData` reads the raw string; `GetLevelSaveName` deserializes into
the **base** type, so TEL answers both without knowing the game's payload.

**Project** — delete the game's level-save extensions. Games with a payload define
`class XLevelSaveData : LevelSaveData` and use the generic pair. `Has`/`Clean` call sites are
unchanged. Anything the old `CleanLevelSaveData` also wiped (hint/lens state in WordGame) must move
to the game's call site.

## 5. Settings reorganised

### SystemSettings gains the build/device flags

**TEL** — `Debug`, `FrameRate` and `IgnoreConnection` moved from `GameStartSettings` to
`SystemSettings`; `ISystemService.StaticSettings` is **deleted** (it was `GameStartSettings`).
`IgnoreConnection` now sits with `PlayOfflineForPayers`/`PlayOfflineNoAds`, so `CanPlayOffline`
reads one asset.

**Project** — repoint every `Debug` reader to `ISystemService.SystemSettings.Debug`. In PopDrop:
`UICoreSystem` and `MenuSceneStarter` switched from `IGameGenericService` to `ISystemService`;
TEL-side `OfferUIView` and `LunarConsoleStartAction` were updated in the library.

Delete any hardcoded `Application.targetFrameRate = 60` in scene starters — `EntrySceneStarter`
applies `SystemSettings.FrameRate` and it persists across scene loads. `EntrySceneStarter` holds the
asset by `[SerializeField]` (it runs before services), so its field became `SystemSettings`.

### GameStartSettings → GameSettings

**TEL** — renamed, reduced to plain public fields, and now:

```csharp
public enum WinFlow { Next, Menu }

public bool AutoRestartLevel;

[Header("Ads")]
public bool AdsOnQuit = false;
public bool AdsOnRestart = true;

[Header("Win flow")]
public WinFlow WinFlow = WinFlow.Next;
public List<int> WinFlowExceptionLevels = new();
```

Removed: the field/property sugar, `OnDataChanged`/`BroadcastUpdate`, `HideRewardsAds`,
`EditorDebugStartLevelIndex`, `EditorStartFromPrefLevel` (all unused — the last two fed
`CoreSceneStarter.GetStartLevelIndex()`, itself dead), and `SkipInters` (see below).

`WinFlow` replaces `SkipMenuRedirectOnLevelComplete`. The enum is the default destination after a
win; the list is the levels where the opposite applies, in **designer numbering** (`index + 1`) for
the **completed** level. The old list held the *next* level's raw index, so entries shift.
Empty list = pure strategy.

`NoAdsOnQuit` became `AdsOnQuit` (inverted) plus `AdsOnRestart`; `Next` always allows ads.

**Project** — apply in the level execution system:

```csharp
private bool AreAdsAllowed(FlowAction flow) => flow switch
{
    FlowAction.Quit => _gameSettings.AdsOnQuit,
    FlowAction.Restart => _gameSettings.AdsOnRestart,
    _ => true,
};

private FlowAction ConvertNextAction()
{
    var completedLevel = ExecutionData.Value.LevelIndex + 1;
    var winFlow = _gameSettings.WinFlow;
    if (_gameSettings.WinFlowExceptionLevels.Contains(completedLevel))
        winFlow = winFlow == WinFlow.Next ? WinFlow.Menu : WinFlow.Next;
    return winFlow == WinFlow.Next ? FlowAction.Next : FlowAction.Quit;
}
```

To keep the old WordGame behaviour ("menu after every win except the first level"):
`WinFlow = Menu`, `WinFlowExceptionLevels = [1]`.

### SkipAds moved to AdsConfig

**TEL** — `AdsConfig` gained `SkipAds` (next to `TestMode`); `AdsService.SkipAds` now reads/writes
`_settings.Config.SkipAds` instead of being a runtime-only property. It stays out of `AdsSettings`
because that is the remote-tunable surface.

**Project** — delete `GameStartSettings.SkipInters` and the bridge that pushed it into
`IAdsService.SkipAds` (in PopDrop this was the only reason `GameGenericService` injected
`IAdsService`). Debug UIs set `IAdsService.SkipAds` directly.

## 6. Game service split

**TEL** — new `Runtime/Services/GameService/`:

```csharp
public interface IGameService : IService
{
    GameSettings GameSettings { get; }
    LevelsTable LevelsTable { get; }
    LevelSettings GetCurrentLevel();
}
```

`GameService` implements it and owns the serialized `_gameSettings`, `_levelsTable`, `_sortTable`,
the level sorting (`SortLevelsByOrder` / `SortLevelsByNames`) and
`protected UpdateCycles(lastVersion, version, fromLevel)` (was `UpdatePrestige`).
`Remote/GameSettingsSerializable.cs` carries the nullable `GameSettingsRemoteModel`
(`FromSettings`/`ToSettings` are `virtual` so projects can extend).

**Project** — `IGameGenericService`/`GameGenericService`/`GameplaySettings` become
`IPopDropGameService`/`PopDropGameService`/`PopDropGameSettings`, deriving from the TEL types and
moved into the game folder with `PopDrop.*` namespaces.

- `PopDropGameSettings : GameSettings` — the two settings assets **merge into one**.
- Expose the derived settings with `public new PopDropGameSettings GameSettings => (PopDropGameSettings)base.GameSettings;`
  (same shadowing pattern as `LevelsTable`).
- `[Inject] Construct` → `ConstructDerived`.
- The project's `MutableLevels` cast disappears: TEL's `LevelsTable.Levels` **is** the backing list.
  A derived table that shadows `Levels` with a copying view only allocates for derived-typed
  references, so consumers should read the table through `IGameService`.
- Version migration (`UpdateVersion`) stays project-side; replace `UpdatePrestige` calls with
  `UpdateCycles`.

## Serialized data checklist

None of these break the compile. Work through them after the code migration:

1. **`ServicesInstaller.asset` RefIds** — the `SerializeReference` blocks store the class name and
   namespace. Update:
   - `GameGenericService, WordGame.Services` → `PopDropGameService, PopDrop.Services`
   - `GameplaySettingsSerializable, WordGame.CoreSystems` → `GameSettingsSerializable, TapEmpire.Services`
     (its field also renames `_gameplaySettings` → `_settings`, from `RemoteSerializableBase`)
   - remove the `<StaticSettings>k__BackingField` entry from `SystemService`
   - point `_gameSettings` at the merged settings asset; delete the `_gameplaySettings` entry
2. **Settings assets** — `GameStartSettings.asset` → `GameSettings.asset` (keep the `.meta` so the
   GUID survives). Rename the serialized keys `_debug`/`_autoRestartLevel`/etc. to `Debug`/
   `AutoRestartLevel` (the sugar removal), move `Debug`/`FrameRate`/`IgnoreConnection` into
   `SystemSettings.asset`, add `SkipAds` to `AdsConfig.asset`.
   PopDrop keeps the merged asset at `_LibraryAssets/Scriptables/GameSettings.asset` with the fixed
   name so `ProjectPathSettings.GameSettingsPath` still resolves — the type is the derived one.
3. **Scenes** — the `CoreSceneReferences` / `CoreSceneInstaller` GUID and field renames from section 2.
4. **Remote config** — the token `"GameplaySettings"` is now `"GameSettings"`, owned by TEL, and the
   payload shrank to the fields listed in `GameSettingsRemoteModel`. Update the Firebase entry.

## Behaviour to verify after migrating

- Level auto-wins when `StepsDone >= StepsTotal` (previously the caller decided).
- Win flow: check the exception list was converted from *next raw index* to *completed designer level*.
- Ads on quit/restart follow the new booleans.
- Frame rate comes only from `SystemSettings.FrameRate`.
